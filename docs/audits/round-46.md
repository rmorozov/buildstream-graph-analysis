# Audit round 46: three field errors and a slowing loop

Run on 2026-08-27, while the sibling executes the round-45 slate —
so no landing to verify; the round takes the user's four
observations, reproduces each with measurements, and files them.

## The three field errors, reproduced

Each was reproduced with numbers before anything was filed.

**The trimmed names** (`UX-333`): worse than reported. On 3,000
processes with realistic 560-character compiler argvs, the current
`cmd[:120]` interned the entire workload to **two unique names** —
compiler command lines share their flags prefix and differ at the
end, so thousands of different compiles render as
identically-named slices. The fix is nearly free done right: full
command as the interned name with the `debug.cmd` duplicate
dropped costs **+8.4 % gzipped, +0.4 % raw** (keeping both would
pay the string twice: +22.8 % gz).

**The CSP errors** (`UX-334`): eleven `style-src-attr` violations
per page boot, all from one path — the exhibit tick labels pass a
`style:` attribute through `drawings.js:123` while the server
sends `default-src 'self'` with no `style-src`. And Chrome
*enforces*: every tick label computes `left: 0px` and piles at the
exhibit's left edge on served pages — the export, which has no
CSP, renders them correctly, so the served page is the broken one.
The same console carries four 404s per boot (favicon plus the
optional-payload probes) and ~200 DevTools accessibility issues
(filter inputs with neither ids nor labels). The user asked for a
guard as much as a fix, and the round designs it: the Chromium
walks capture console messages and violation events and fail on
any — which also nets `UX-335`'s class.

**The start_time TypeError** (`UX-335`): an honest split verdict.
The literal string appears **nowhere in this codebase and never
has** — zero hits in every served asset, the export, and
`git log -S` over all history; zero exceptions booting every page
live. The field error came from outside the viewer (most likely a
browser extension's content script on the localhost page; one
incognito check on the field machine settles it). But the failure
*class* reproduced immediately: one `null` row in `store.json`
collapses the whole report to "Could not load this run" — a
renderer indexes the row before checking it, and `boot()`'s single
page-wide try/catch makes one section's throw everyone's funeral.
The filing moves error containment to the section boundary.

## The loop, re-tooled

The fourth observation is about the factory, not the product: the
implementing session slows as the code and suite grow. Round 46
measured the levers and filed `UX-336` with five, all additive and
none through the discipline: the suite runs parallel
(measured: `pytest-xdist -n auto` takes the full suite from ~375 s
to **148.7 s — 2.5×, 4,014 passed, zero failures, zero races**,
because every server already binds ephemeral ports; the one
adoption step left is diffing the skip census once). The
measurement also corrected an assumption: the browser walks are
already frugal (three files, one shared Chromium each), and the
real problem is that the "fast" tier is not fast — small+medium is
3,849 tests at 335 s, five and a half minutes that is nobody's
inner loop; re-tiering by fresh measurement is lever three; a change-scoped `make test-touching` gives the
inner loop seconds while the full suite keeps its
once-before-commit place; the browser clauses become their own
tier sharing one Chromium instance; the close ritual's mechanical
tail (Outcome skeleton, mutation-record table, row move) is
generated by a helper the verify skill cites; and the two largest
viewer modules split along chapter seams — page-cost neutral,
edit-cost real.

## Filed

`UX-333` (the name is the whole command, Medium), `UX-334` (a
console the page keeps clean — the fix and the guard class, High),
`UX-335` (the start_time read, Medium), `UX-336` (the loop
re-tooled, High).

## Standing

Priority: **UX-336's xdist adoption is a one-line dependency and a
skip-census diff away from a 2.5× faster loop — it goes first**,
then UX-334 (a real rendering defect on served pages, not just
noise), then UX-333 (the two-names finding makes it more than
polish), with UX-335's containment riding the next viewer pass.
None of this collides with the round-45 slate the sibling is
executing. And one lesson for the audit loop itself: the user's
console had been shouting about the tick labels for some unknown
number of rounds — nothing listened to the browser's own error
channel until this round wired it in. The cheapest guards are the
ones the platform already emits.
