# Manual real-project capture on CircleCI

Connect this GitHub repository as a CircleCI project, then use **Pipelines → Trigger Pipeline**. Select a branch containing `.circleci/config.yml`; add pipeline parameter `run_capture` (boolean) with value `true`. The workflow has no scheduled runs, and ordinary pushes use the default `false`, so they do not start a capture. Set `jobserver` to `auto` to exercise the jobserver; leave it `off` for comparison. Keep `fdsdk_ref`, `target`, `builders`, `max_jobs`, `capture_mode`, `trace_opens`, and `trace_spine` identical between comparison runs. The default target is intended for `incremental` captures; choose a smaller whole closure for `cold`.

The job runs on a CircleCI Linux VM (`large`, 4 vCPUs and 16 GiB), installs BuildStream and bga, clones the pinned freedesktop-sdk revision, warms and cuts the incremental rebuild set, then captures the build and records its analysis. Download `fdsdk-capture` from the job's Artifacts tab, including partial results if the build fails. Captures stay in CircleCI artifacts; this job never moves the GitHub `captures/fdsdk-latest` branch or writes other capture branches. No GitHub write token is required.

**Free-plan limit:** CircleCI currently caps each Free-plan job at **one hour**. The GitHub workflow documents approximately 65 minutes for a default incremental capture on its runner, so the same run might time out here, especially with tracing or jobserver overhead. The `large` VM's extra CPU may shorten it, but that must be measured. A cold capture of the default target is known to exceed the job budget. Check CircleCI's current credit allowance and VM availability before dispatching repeated runs.

If the job times out, its exit handler attempts extraction and analysis of the partial build log and the `store_artifacts` step retains `capture/`. A hard VM termination may prevent the exit handler from running; inspect `build.log` and `native-report.json` before treating such a capture as complete. Results from a 4-vCPU CircleCI VM should be compared only against runs with matching capture parameters and runner topology, not merged into a GitHub-hosted baseline without checking those differences.
