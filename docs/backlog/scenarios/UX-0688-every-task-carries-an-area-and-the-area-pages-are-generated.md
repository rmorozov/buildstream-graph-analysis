# UX-688: every task carries an area, and the area pages are generated

**Priority:** High | **Status:** 🔴 Not Started | **Depends on:** UX-501 (the derived index), UX-239 (the module tree) | **Serves:** the session doing impact analysis or a test plan without rescanning 682 files | **Topic:** docs

## Motivation

```text
task header fields         Priority · Status · Depends on · Serves · Topic — no Area
topics                     8, viewer the largest at 156 of 682
generated indexes          README.md open rows, closed.md — nothing per area
Depends on                 563 of 682 name an id — a graph nobody walks
```

Impact analysis and test planning start by rescanning hundreds of
task files because the only grouping is eight topics. A tree of new
files would cost a round and break 682 guarded links; the hierarchy
the brief asks for is a *view*, derived.

## Required Fix

- An `**Area:**` field — a path under the module tree the fixing
  guide's §6 already maintains (`capture/hook`, `capture/spine`,
  `analysis/floors`, `viewer/rail`, `viewer/tables`, `contracts`,
  `process/guards`, …) — derived once for the 682 by the files each
  closing commit touched (`git log --grep 'UX-NNN'` → paths → area),
  reviewed where ambiguous, and required by the row guard from this
  item on.
- `docs/backlog/areas/<area>.md` generated by the close tool
  (`--check --write`): the area's modules, contracts, guards
  (touch map + census), guides, and its open and closed tasks with
  their one-line rows and Depends-on edges. The README's topic table
  gains an area column; the pages are the hierarchy.

## Out of Scope

- Moving task files — the flat directory and its links stay.
- A second taxonomy — areas are the module tree; topics stay as the
  coarse eight.

## Acceptance Test

Every task from this item on carries an Area the tree knows;
`--check --write` regenerates the pages and the counts agree;
mutation: an area not in the tree — red naming the file.
