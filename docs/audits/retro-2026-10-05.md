## Proposals

Each is marked `optimization`. The architect shapes them; this report
does not.

1. **A pinned dev dependency is checked against the Python floor on the
   pull request.** It would compare every `dev` pin's `requires_python`
   with `requires-python`, or run a `pip install --dry-run` on the
   floor version. Then a merge cannot take main's oldest cell red
   unseen. The fix itself is a decision: either drop 3.9 (EOL since
   2025-10) or put `python_version >= "3.10"` on the pin and skip the
   property tests below it.
2. **§7's guard table in `docs/design/styleguide.md` is derived, or
   guarded.** The same drift was filed four times this week (r155,
   r158, r160, r163, all at `styleguide.md:2300`). Each time, a round's
   new guards were missing from §7's table, and all four were swept by
   hand in r169. `test_the_styleguide_names_its_guards.py` checks
   sections, not that a new guard is named.
3. **`dev_retro.py` counts a filing once, by the round it was filed
   in.** A line resolved inside the window should not count again.
   `Class:` should count as its category (`product`, `bookkeeping`,
   `optimization`), not as unclassed. A bare `test_*.py` in `Guard:`
   should key as the file. That would cut the unclassed count from
   214 to about 64, and the weekly count would mean new drift.
