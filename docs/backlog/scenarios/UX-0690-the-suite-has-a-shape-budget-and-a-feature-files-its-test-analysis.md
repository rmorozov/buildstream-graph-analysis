# UX-690: the suite has a shape budget, and a feature files its test analysis

**Priority:** Medium | **Status:** 🔴 Not Started | **Depends on:** UX-238 (the tiers), UX-400 (the population sweep), UX-498 | **Serves:** R8 reading whether the suite is balanced; the implementer writing the right guard | **Topic:** guards | **Shape:** judgement

## Motivation

```text
tests/unit                     472 files, one claim each · 7,206 tests
journey-shaped files           3
browser-boot files             36 = 42.8 % of CI's 1,497 reference seconds (after UX-523's 2.54× cut)
bst-marked (enormous)          21 files
property-based / seeded        0   (hypothesis: only the English word; random.seed: 0)
```

The tiers are measured by duration and say nothing about *purpose*;
the brief's "balance of big and enormous with small and medium" has
no number to be held to, and the test-analysis step (`decompose` §2's
partition table) was left unguarded in `UX-498` as unmeasured — three
rounds later it is measurable.

## Required Fix

- A shape table derived from the tree — per-claim unit · population
  sweep · journey · browser · enormous — with counts and CI seconds,
  regenerated by the close tool and printed in every round document's
  Standing; a budget per row (browser ≤ 40 % of seconds; journey
  files ≥ one per published contract) that the tier guard holds.
- Every feature filing's decomposition names the input classes its
  guards cover and the journey it extends; the row guard requires
  the block for `Topic: analysis|viewer|capture` items from this
  item on (the `UX-498` decline, revisited on the three rounds since).

## Out of Scope

- Re-tiering by purpose — duration stays the tier's rule; purpose is
  a second, derived view.

## Acceptance Test

The shape table's counts match `ls`/markers; mutation: add a browser
file past the 40 % row — the budget guard reds; a feature filing
without the block — the row guard reds.
